# Vault Instructions

This directory is an Obsidian vault managed by the **agents-memo** plugin. It is a
knowledge base, **not a code directory** — the wiki is for synthesized knowledge,
not for re-deriving things from source.

Generated by `/memo:init` — keep this file in sync with your conventions.

## When to engage the vault

- The user plans or brainstorms → query the wiki for context (read `wiki/hot.md`
  first, then `wiki/index.md`, then drill into domain pages).
- The user asks a question that prior notes might answer → query the wiki.
- The user wants to file something for later → note / daily / save operations.

## When NOT to engage the vault

- General coding, build, or test work. Do not read the vault for routine code
  questions.

## Vault I/O

- All vault reads and writes go through the **Obsidian CLI** (`obsidian <verb>`),
  never direct file edits. See {{PLUGIN_ROOT}}/scripts/obsidian-cli.sh.
- Obsidian must be running — the CLI cannot reach a closed vault.
- Read {{PLUGIN_ROOT}}/skills/vault-ops/SKILL.md for CLI patterns, slugging, and
  indexing rules.

## Structure

- `wiki/` — knowledge base: `hot.md` (session cache), `index.md` (registry),
  `concepts/`, `entities/`, `sources/`.
- `notes/` — inbox: pending and deferred notes (`notes/index.md`).
- `daily/` — daily logs: `YYYY-MM-DD.md`.
- `.raw/` — immutable source documents (never modify).

## Maintenance

- Optional: `{{PLUGIN_ROOT}}/bin/wiki-lint-cron.sh` runs the memo-lint skill on a
  schedule — install as a systemd user timer via
  `{{PLUGIN_ROOT}}/bin/install-lint-service.sh`.
- The `wiki/hot.md` cache is rewritten at session end; `wiki/index.md` and
  `wiki/log.md` are updated on every write.
